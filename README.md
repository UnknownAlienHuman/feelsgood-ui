# FeelsGoodUI

Minimalist Retail UI addon with oUF unit frames, secure action bars, center resources, companion controls, movers, settings, and profile transfer.

## Requirements

- World of Warcraft Retail `12.1.5`
- Interface `120105`
- FeelsGoodUI `0.0.69`
- External required dependency: `oUF`
- Saved variables: `FeelsGoodUIDB`

Copy the `FeelsGoodUI` directory into `World of Warcraft/_retail_/Interface/AddOns/`, install `oUF`, and restart the client or run `/reload`.

## Runtime policy

Restricted/Secret Values are gated before Lua inspection. Unit Frames and Center Bars own those gates directly in their render paths. Configuration access has an explicit read/write boundary: `DB:ReadSection` never creates or repairs SavedVariables, while `DB:EnsureSection` is reserved for Settings, migrations, and other validated write owners. Core presentation services and every feature runtime use the pure reader. UnitFrames runtime/render paths are read-only consumers of normalized configuration: missing sections, sizes, scales, and target-aura mode resolve through local immutable fallbacks and are repaired only by DB/Settings/schema owners, never while frames are being created or refreshed. oUF frame, aura-container, observer-hook, low-health, and unit-watch state stays in addon-owned weak registries; native watch failures propagate instead of publishing a false attached state. Each restricted-value producer is queried once, ordinary data stays on the normal path, and inaccessible health, power, classification, aura-source, and rune values go only to documented native presentation sinks or an explicit unavailable state. ActionBars permanent secure, SettingsPanel, action-change, holder/button auto-hide, and state-layer hooks are result-bearing and replacement-safe: target/method edges live in weak registries, installed partial edges remain inert until full initialization publishes the active owner, init/callback summaries publish only after successful registration, callbacks resolve that current active owner, detach invalidates a generation record before unregistering callback handles, so an old callback remains inert even when cleanup fails; owners are released and retry installs only missing edges. Holder/button hooks remain result-bearing: weak registries own holder/button state, each `HookScript` edge is published only after success, callbacks resolve the current module record, partial registration retries without duplicate textures/hooks, and failures reach Apply instead of leaving a false attached state. Protected action-bar and Blizzard-frame mutations remain deferred outside combat. ExperienceBar suppresses native status tracking through a verified per-frame/per-property alpha/mouse journal: unreadable properties are never mutated, every write is read back, hook/suppression/restore failures propagate to Apply/Lifecycle, unresolved restore records remain retryable, and newer conflicting external values are preserved. It never hides or unconditionally shows foreign frames and reasserts only verified suppression after Blizzard refreshes. CenterBars follows the same verified property-journal policy for Blizzard class-resource frames: alpha and mouse channels are captured only when readable, every suppression and restore write is checked by readback, hook/write/restore failures propagate to Apply/Lifecycle, unresolved restores remain retryable, frame replacement cannot adopt a new instance until the old ownership record releases, and newer conflicting values are preserved. Combat-sensitive CenterBars apply is centrally deferred and never guesses visibility or calls native setup. Styling helpers follow the same boundary: `Media:CreateBorder` keeps border records in a weak-key owner registry and never writes `__fgui*` metadata onto Blizzard or third-party frames. Companion micro-menu/bag hook state, compact-count font strings, and summaries likewise live on the Companion owner. Micro source, reset, bag-texture, and expand callbacks publish hook state only after successful registration; weak-key records are reconciled on replacement, stale-object callbacks are inert, partial failures retry only the missing edge, and the backpack texture hook never recursively calls `UpdateTextures`. Layer apply functions return explicit results, a failed layer restores already-applied presentation before reporting failure, and transient pet-button creation is queued for an event-driven retry instead of disabling the feature. PetActionButton takeover is journaled property-by-property in `CompanionPetState`: structural layout and dynamic visibility have separate ownership, component-object replacement reopens the snapshot, mover preview updates the same managed journal, unreadable mutable components are refused before mutation, and original/managed textures, masks, text, cooldown and native PetActionBar alpha restore only while still addon-owned. ActionBars keeps button layers, owner pointers, callbacks, styles, typography anchors, cooldown timer caches, and hotkey policy in weak-key owner registries rather than stamping `_fgui*` fields onto Blizzard ActionButton/FontString/Cooldown objects. It snapshots the complete native `GetActionBarToggles()` state before takeover and restores it exactly on detach; a compact per-character recovery marker preserves that baseline across `/reload` or interruption and is restored on `PLAYER_LOGIN` before ActionBars reattaches. Native sidebar state is never imported by mutating the addon profile, and unchanged toggle sets are not rewritten. Detach invalidates queued action-bar work, disables permanent hook side effects, and performs a narrow post-combat Blizzard-shell restore when teardown occurs during combat. Shared debounce requests treat an existing keyed timer as a successful coalesced request; cancellation always invalidates its generation before lifecycle teardown. Apply handlers propagate explicit failure: settings commit only after every key in the batch succeeds, while a `false` result or exception rolls back the batch and restores already-applied runtime owners. Panel undo/reset operations participate in the same transaction: history is consumed or invalidated only after every required apply key commits, and failed or partially deferred batches restore both profile sections and the exact undo stack. Feature lifecycle transitions are result-aware and reentrancy-guarded: failed attach/apply paths clean up without publishing `enabled=true`, independent modules continue loading, and Unit Frames or Center Bars that start disabled can later initialize and acquire their event owners normally. Shared animation fades and keyed timers keep state in weak-key registries rather than arbitrary frame/owner fields; the dead generic cooldown cache helper is removed. Minimap drag uses a detached LibDBIcon runtime proxy and a weak-key hook registry on the addon side: per-frame movement never touches SavedVariables, the exact button that starts a drag owns its stop/cancel path, mouse-up creates one validated `Settings:SetTx` transaction, and failed apply/cancel restores the persisted position. The dead addon `radius` field is removed because LibDBIcon radius is library-global rather than per button. Options layout hooks and mover-panel listeners use addon-owned weak registries: hook ownership is published only after `HookScript` or listener registration succeeds, partial failures retry only missing edges, rebuilt widgets/panels do not inherit stale markers, and permanent callbacks resolve the current record at dispatch time. General commands and options never write runtime settings directly: debug, performance overlay, target-aura mode, and minimap state all flow through `Settings:SetTx` and the shared apply/rollback journal; `RuntimeSettings` is the single apply owner for debug and performance presentation. Mover registration is replacement-safe and result-bearing: same-frame descriptor updates roll back when label or handle refresh fails, replacement prepares the new overlay before retiring the previous owner and cleans every old script/handle, stale frames cannot apply another owner’s key, apply reports missing/invalid stored positions, unlock presentation restores the previous state on error, hot-path owners retain frame-specific mover readiness, and feature `_inited`/`_created` flags publish only after registration and position apply succeed. Mover state follows the same ownership rule: continuous move/resize is runtime-only preview, while mouse-up, wheel, inspector, lock state, editor settings and position resets commit validated writes once through `MoversTransactions`; failed commits reapply the persisted owner state. Profile import is staged on a detached snapshot and replaces the live profile through one profile-wide transaction; success is published only after every immediate and combat-deferred runtime owner commits, while a late failure restores the prior profile and history. A temporary SavedVariables recovery record restores any import interrupted by `/reload`, logout, or client termination before terminal commit and overlays newer edits onto the recovered profile.

## Validation

Run the deterministic static check from the addon root:

```bash
npm ci
npm test
```

The checker parses first-party Lua, validates TOC paths and duplicates, and enforces critical load-order constraints. Static checks do not replace client validation; record each tested build and result in [`docs/REGRESSION_MATRIX_1_25.md`](docs/REGRESSION_MATRIX_1_25.md).
